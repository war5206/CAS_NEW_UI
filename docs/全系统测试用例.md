# CAS 智慧控制系统 — 全系统测试用例

> 适用范围：CAS-NEW-UI（React + Vite + Electron）桌面端应用  
> 版本：v1.0  
> 编写日期：2026-07-09  
> 测试方式：以手工测试为主，关键路径可基于 Playwright / Cypress 自动化

---

## 一、测试环境与通用前置条件

| 项 | 说明 |
| --- | --- |
| 运行环境 | Windows 10 / Windows 11，Electron 打包版或 `npm run dev` 开发模式 |
| 推荐分辨率 | 1920×1080（设计基准分辨率） |
| 浏览器内核 | Chromium（Electron 内置） |
| 后端依赖 | FinforWorx 后端服务可正常访问，`VITE_API_BASE_URL` 配置正确 |
| 默认账号 | `admin` / `FinforWorx3.0`（可通过 `.env` 覆盖） |
| 数据准备 | 已存在至少 1 套可登录系统；标准款与大剧院（dajuyuan）两种项目形态均需覆盖 |

### 通用优先级定义

- **P0**：核心主路径，阻塞发布，必须 100% 通过
- **P1**：重要功能，允许少量非阻塞缺陷
- **P2**：体验/细节类，可后续迭代优化

## 十七、测试执行建议

1. **冒烟测试**：每次构建后优先执行所有 P0 用例。
2. **回归测试**：每次功能迭代后，执行对应模块全部用例及相关 P0 用例。
3. **全量测试**：大版本发布前，按模块顺序执行本用例集。
4. **缺陷记录**：建议使用缺陷编号关联用例编号，便于追溯。
5. **自动化扩展**：可将 P0、P1 用例中页面跳转、元素渲染、保存/确认类用例优先转化为 UI 自动化脚本。
